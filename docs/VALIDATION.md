## 자동 검증

- `npm test`: **153개 통과**, 실패 0개, 로컬 macOS 건너뜀 0개.
- `orca plugin test . --json`: 같은 153개 통과, runner exit 0.
- `npm run check`: JavaScript 문법, manifest 진입점, 설치 문서 확인.
- `orca plugin check . --json`: manifest 유효, 오류 없음.
- `git diff --check`: 통과.

패널 테스트의 DOM 경계 모형은 레이아웃 검증을 대체하지 않습니다. Orca의 HTML 패널도 manifest 검사만으로 화면이 검증되지 않으므로 아래 브라우저/네이티브 확인을 별도로 수행했습니다.

CI 결과는 [GitHub Actions](https://github.com/torisKR/orca-toris-neon/actions)에서 해당 커밋으로 확인합니다. Windows의 심볼릭 링크 생성 권한에 의존하는 사례는 테스트에 명시된 조건으로 건너뛸 수 있습니다.

## 화면과 사용자 흐름

localhost 미리보기는 실제 자격 증명과 에이전트를 사용하지 않는 고정 샘플입니다.

- 인계 14개를 **6 → 12 → 14개**로 불러오고 마지막 페이지까지 접근.
- 보관 실행은 목록에서 선택한 후 상세 이벤트를 불러옴.
- 오늘·어제 탭, 오늘 이벤트 **20개**의 더 보기 확인.
- 11개 노드와 **12개 의존성 화살표** 표시.
- **320, 390, 480, 768, 1180px** 너비에서 가로 넘침 없음.
- 480px에서는 2열, 768px 이상에서는 3열 그래프. 좁은 패널은 상세를 그래프 위에 배치.
- 낮은 위치에서 탭을 바꾸면 scrollY가 0으로 복귀. 좁은 화면에서 단계 클릭 후 상세 제목이 고정 메뉴 아래 약 65px에 보임.
- 다크 Today 화면, 라이트 Play 화면, 실제 Orca 라이트 Today 패널을 스크린샷으로 확인.
- 실제 Orca 개발 플러그인의 `state.get(summary)`, `runs.get`, `today.snapshot`, `play.list` 응답 확인.
- 실제 Today의 한국 날짜, 어제 일지, 페이지 정보, 변경된 소스에 대한 stale 표시 확인.

## 측정한 성능 변화

| 측정 범위 | 결과 | 해석 |
|---|---|---|
| 실제 Orca 상태 JSON, 활성 0/보관 4 실행의 당시 데이터 | full **55,308 B** → summary **24,845 B**, **55.1% 감소** | 호스트 목록을 포함한 UTF-8 직렬화 크기. 다른 프로젝트 수·기록량에서는 달라짐 |
| 고정 미리보기 데이터 | full **59,817 B** → summary **11,829 B**, **80.2% 감소** | `Buffer.byteLength(JSON.stringify(value))`, 합성 데이터 |
| 큰 보관 이력 회귀 fixture | summary가 full보다 **95% 이상 작음** | evidence 원본과 상세 조회 보존도 함께 검증 |
| Today의 40개 작업 공간 / 6개 페이지 fixture | fingerprint **3회**, 최대 동시 검사 **2개** | 비교 기준 없는 기록과 중복 경로를 제외 |
| 인증 401 / 12개 출시 조회 fixture | 이미 전송 중인 최대 **3개** 이후 추가 전송 중지 | 실제 API 속도/사용량 측정이 아닌 요청 수 회귀 |
| 같은 프레임의 패널 이벤트 묶음 | 화면 갱신 및 선택한 실행의 상세 요청을 합침 | 오래된 revision과 응답도 무시 |

표시용 호스트 목록만 짧게 캐시하며 실제 실행·복구 판단은 캐시하지 않습니다. Today의 파일 검증은 진행 중인 동일 요청만 공유하고 완료된 지문을 캐시하지 않습니다. 전체 근거와 이력은 삭제하지 않고 상세 API로 유지합니다.

이는 응답 크기와 IO/호출 수를 확인한 결과이며 화면 전체가 같은 비율로 빨라진다는 의미는 아닙니다.

## 검증 범위의 한계

이번 점검에서 실제 Google 서비스 계정 조회, Play 업로드, 완성 앱 전체 제작을 새로 실행하지 않았습니다. Play 오류·캐시·저장 경합은 모의 응답으로 검증했습니다. 기존 Orca 첫 프롬프트 미전달 시의 명시적 1회 복구 흐름은 유지하며, 테스트가 호스트/외부 서비스의 모든 동작을 보증하지는 않습니다.
