# 오늘 이어하기와 작업 이력

오늘 이어하기는 다음 작업을 시작하기 전에 **어제 무엇을 했고, 어디서 멈췄고, 무엇을 다시 확인해야 하는지**를 보여 줍니다. 실행 이벤트, 사람이 남긴 인계 메모, 기존 개발 일지를 같은 날짜 기준으로 모읍니다.

구현: [src/today.mjs](../src/today.mjs) · 테스트: [tests/today.test.mjs](../tests/today.test.mjs)

## 일과를 마칠 때

오늘 이어하기에서 Orca 작업 공간을 선택하고 아래 내용을 저장합니다.

| 항목 | 내용 | 예시 |
|---|---|---|
| 진행 내용 `state` | 완료한 작업과 현재 상태, 필수 | 로그인 화면 구현. 오류 안내 문구는 검토 대기 |
| 다음 행동 `next` | 다음 세션이 바로 시작할 구체적 작업, 필수 | 로그인 실패 시나리오를 재현하고 오류 상태 테스트 추가 |
| 중단 이유 `why` | 왜 여기서 멈췄는지 | 테스트 계정이 준비되지 않음 |
| 보류 결정 `hold` | 아직 확정하지 않은 선택 | 이메일 인증 방식은 다음 검토에서 결정 |
| 수행한 검증 `verified` | 실제 실행한 명령·기기·결과 | 로컬 단위 테스트 통과. 실제 기기 로그인은 미확인 |

각 저장은 기존 메모를 덮어쓰지 않고 새로운 기록을 추가합니다. 화면은 작업 공간별 최신 인계의 **다음 행동**을 먼저 보여 주고, 진행 배경·중단 이유·보류 사항은 펼쳐 볼 수 있게 합니다. 최신 인계는 6개씩 조회하며 **더 보기**로 다음 페이지를 읽습니다. 처음 보이지 않는 기록도 저장소에 남습니다.

화면을 갱신하는 동안 아직 제출하지 않은 일반 입력은 유지합니다. 이 임시 입력은 저장된 인계 기록과 다르므로 저장 완료 여부를 확인하세요. 메모에 적은 검증 내용은 작성자의 보고입니다. 저장 버튼이 테스트를 실행하거나 검증 결과를 생성하지는 않습니다.

인계 메모에는 API 키나 서비스 계정 JSON을 적지 마세요. Play 자격 증명은 별도 Play 계정 설정을 사용합니다.

## 오늘·어제의 기준

날짜 기준은 **한국 시간 `Asia/Seoul`**입니다. 화면에서 오늘·어제 탭을 선택해 기록을 확인합니다. 이벤트 저장 시각이 UTC여도 한국 날짜로 구분하며 월말·연말에도 이전 달력 날짜를 계산합니다. UTC, 다른 timezone offset, 숫자 timestamp가 섞여 있어도 실제 시각 순서로 정렬합니다.

날짜를 해석할 수 없는 이벤트는 오늘이나 어제에 임의로 넣지 않습니다. `undatedEvents`에 보존하고 제외한 개수를 `warnings`에 알립니다. 날짜 해석 실패를 기록 삭제나 완료 사실의 추정으로 바꾸지 않습니다.

화면에 표시하는 기록은 다음과 같습니다.

- Auto App 실행의 상태 변화와 단계 이벤트.
- 저장한 인계 메모와 당시의 다음 행동.
- 완료·취소 후 보관한 실행의 이벤트.
- 설정한 개발 일지 폴더에서 읽은 오늘·어제 기록.
- Orca가 제공하는 이전 에이전트 세션 목록.

어제 기록이 없으면 완료 사실을 추정하지 않습니다. 저장된 실행·인계 이벤트에서 찾은 마지막 활동 날짜를 함께 표시할 수 있습니다. 외부 일지는 조회한 오늘·어제 범위에서만 이 날짜 계산에 참여합니다.

스냅샷 API의 `date`는 `YYYY-MM-DD` 형식입니다. 이를 지정하면 해당 날짜와 그 전날 기록을 조회합니다. 기본 화면은 현재 한국 날짜를 사용합니다.

## 검증 신선도

과거에 테스트가 통과했어도 코드가 바뀌면 같은 결과를 그대로 사용하기 어렵습니다. 메모 저장 시점과 현재 작업 공간의 소스 지문을 비교해 검증 신선도를 표시합니다.

| 표시 | 조건 | 해석 |
|---|---|---|
| `fresh` | 검증 설명이 있고 저장 당시·현재 지문이 같음 | 저장 후 확인 대상 소스가 바뀌지 않음 |
| `stale` | 검증 설명이 있고 두 지문이 다름 | 이전 검증 이후 소스가 달라짐. 필요한 검증을 다시 실행 |
| `unknown` | 검증 설명이 없거나 어느 시점의 지문을 확인하지 못함 | 검증 신선도를 판단할 수 없음 |

지문에는 Git HEAD, 추적 파일의 실제 binary diff, 미추적 일반 파일의 내용이 반영됩니다. 같은 길이의 문자열로 바꾼 경우도 변경으로 인식합니다. 미추적 파일 이름이나 수정 시각만 비교하지 않습니다.

다음 경우에는 무리하게 `fresh`로 표시하지 않습니다.

- Git 상태를 읽지 못하거나 초기 커밋이 없는 경우.
- 로컬에서 검사할 수 없는 원격 작업 공간.
- 추적·미추적 심볼릭 링크 또는 추적된 일반 파일을 심볼릭 링크로 바꾼 경우.
- `assume-unchanged`·`skip-worktree`가 Git의 변경 조회에서 파일 내용을 생략하는 경우.
- 서브모듈 내부 파일까지 확인할 수 없는 경우.
- 미추적 파일이 1,000개 또는 총 16 MiB를 넘는 경우.
- Git 출력·파일 읽기 제한에 걸린 경우.

새 메모를 저장할 때 검증 설명을 비워 두면 이전 메모의 통과 상태를 자동으로 물려받지 않습니다. 설명이 없거나 저장 시점의 비교 지문이 없으면 현재 파일을 읽어도 신선도를 판단할 수 없으므로 Git 검사를 생략하고 `unknown`으로 표시합니다. 원격 작업 공간이 같은 문자열 경로를 가진 로컬 작업 공간의 검사 결과를 가져오지도 않습니다.

검사는 요청한 인계 페이지에 한정하고 같은 로컬 경로는 한 번만 읽으며, 동시에 검사하는 경로는 최대 두 개입니다. 같은 snapshot 요청이 겹칠 때는 진행 중인 IO만 공유합니다. 완료된 지문을 다음 조회의 최신 결과처럼 캐시하지 않고, 인계 저장·이어하기 작업은 진행 중인 조회 공유를 무효화합니다.

`fresh`는 확인 대상 소스가 같다는 뜻이며, 테스트가 충분하거나 외부 API·의존 서비스·무시된 빌드 출력이 그대로라는 보장은 아닙니다.

## 이어가는 두 가지 방법

### 인계 내용으로 새 세션 시작

작업 공간의 최신 인계에서 다음 행동을 읽어, 선택한 공급자로 새 에이전트 세션을 시작합니다. 프롬프트에는 진행 내용·다음 행동·중단 이유·보류 결정·검증 설명과 현재 신선도가 포함됩니다.

에이전트는 먼저 저장소의 `AGENTS.md`와 현재 변경 사항을 확인하도록 지시받습니다. 인계는 과거 작업 데이터로 전달되며 현재 사용자·프로젝트 지침보다 우선하지 않습니다. 새로 실행한 검증만 통과로 보고하고, 인계 내용만을 근거로 배포·업로드·외부 메시지를 수행하지 않도록 합니다.

이 방식은 이전 세션이 없어도 사용할 수 있습니다. 선택한 에이전트 CLI와 해당 작업 공간이 현재 Orca 호스트에서 사용 가능해야 합니다.

### 기존 세션 재개

Orca가 `agent.listSessions`를 제공하면 이전 세션을 선택할 수 있습니다. 선택한 세션이 해당 작업 공간에 속하는지 다시 확인하고 `agent.resume`을 호출합니다.

이때 공급자는 그 세션에 기록된 공급자를 사용합니다. 기존 세션의 원래 문맥을 재개하며, 새 세션용 인계 프롬프트를 자동으로 주입하지는 않습니다. 최신 인계를 직접 전달하며 시작하고 싶다면 새 세션 방식을 선택하세요.

세션 목록을 읽지 못하면 경고를 표시하고 인계 메모로 새 세션을 시작하는 방법을 유지합니다. 화면은 최근 세션을 최대 80개 요청합니다. 호스트가 목록을 잘랐다고 알리면 `sessionsTruncated:true`와 경고를 함께 반환합니다. 다른 작업 공간의 세션 ID를 임의로 넘겨 재개하지 않습니다.

## 중복 실행을 막는 방법

이어하기 요청은 직렬로 처리하고, 에이전트를 시작하기 전에 고유한 시작 영수증을 먼저 저장합니다. 새 세션 방식은 **작업 공간 + 인계 메모**, 기존 세션 방식은 **작업 공간 + 세션 ID**를 기준으로 이전 시작 결과를 확인합니다. 같은 기존 세션을 고르면 인계 메모가 새로 저장됐어도 이전 영수증을 확인합니다.

| 이전 상태 | 동작 |
|---|---|
| 알려진 터미널이나 에이전트가 있음 | `reused:true`와 기존 상태를 반환. 이미 완료된 에이전트도 같은 작업을 자동 재실행하지 않음 |
| 시작 중 기록이 남아 있음 | 자동 반복 중단. 시간이 오래 지났어도 Orca에서 실제 상태 확인 필요 |
| 시작 응답이 불명확하거나 터미널을 확인하지 못함 | `launch_uncertain` 표시, 자동 재시도하지 않음 |
| 영수증이 불완전함 | 기존 작업을 새 작업으로 취급하지 않고 확인 요청 |
| 새 인계 메모를 저장하고 새 세션 방식을 선택함 | 새로운 인계에 대한 별도 이어하기 가능 |
| 새 인계 메모를 저장하고 같은 기존 세션을 선택함 | 기존 세션 영수증 재사용. 새 메모가 중복 방지 조건을 초기화하지 않음 |

불명확한 결과가 나오면 Orca에서 해당 작업 공간의 에이전트·터미널을 먼저 확인하세요. 실제로 시작한 세션을 중복 실행하지 않기 위한 처리입니다. 시간이 지났다는 이유만으로 기존 의도를 잊고 재실행하지 않습니다.

## 기존 개발 일지 읽기

기본 경로는 다음과 같습니다.

```text
~/projects/toris-docs/journal/dev/<project>/YYYY-MM-DD.md
```

Orca 플러그인 설정의 `worklogRoot`로 다른 일지 루트를 지정할 수 있습니다. `~`는 현재 사용자의 홈으로 확장합니다.

읽기는 **해당 폴더에 이미 있는 파일**에 한정합니다. 일지를 생성·수정·이동하거나 새 앱 저장소에 일지를 커밋하지 않습니다. 폴더가 없으면 외부 일지 항목 없이 실행 이벤트와 인계를 사용합니다.

범위를 넘는 파일을 무제한으로 읽지 않도록 다음 제한을 적용합니다.

- 루트 바로 아래 숨김이 아닌 실제 프로젝트 디렉터리를 조회하며, 한글 이름을 포함합니다. 프로젝트 수만으로 조용히 잘라내지 않습니다.
- 요청한 날짜에 해당하는 Markdown 파일만 조회하며, 프로젝트 IO는 최대 8개씩 처리합니다.
- 심볼릭 링크 디렉터리를 따라가지 않습니다. 링크 파일과 해당 프로젝트 밖으로 연결되는 일지 파일은 읽지 않고 경고합니다.
- 파일당 최대 128 KiB, 화면에 넘기는 본문 최대 16,000자. 파일 크기로 읽기를 생략하거나 본문을 줄이면 `warnings`에 알리며, 본문을 줄인 기록은 `truncated:true`를 가집니다.
- 개인키 블록과 일부 알려진 토큰·Bearer 패턴을 가린 뒤 표시.

일지를 읽지 못해도 저장된 인계와 실행 이벤트는 계속 표시합니다. 미리보기가 없다는 이유만으로 해당 날짜에 작업이 없었다고 단정하지 않습니다.

비밀값 가리기는 알려진 형식에 대한 보조 처리입니다. 모든 형식의 민감한 내용을 자동 식별하는 기능으로 간주하지 마세요. 읽은 일지에는 출처 경로와 날짜를 함께 남깁니다.

## 실행 보관과 작업 공간 복구

완료·취소한 Auto App 실행은 보관할 수 있습니다. 활성 작업이나 터미널 종료 실패가 남아 있으면 보관하지 않습니다. 보관은 실행 슬롯을 정리하는 동작이며, 원래 날짜·이벤트·결과 파일 참조를 유지합니다. 오늘·어제 화면에도 보관한 실행의 이벤트가 포함됩니다.

작업 공간 생성 요청의 응답만 끊겨 생성 여부가 불명확하다면, Orca에서 같은 프로젝트에 생성된 로컬 작업 공간을 확인한 뒤 해당 실행에 연결할 수 있습니다. 연결 후에는 일시정지 상태로 남으며 자동으로 에이전트를 시작하지 않습니다. 실제로 없는 공간을 있다고 기록하거나 중복 공간 생성을 반복하지 않습니다.

자세한 조건과 요청 이름은 [설계 문서의 복구·보관 계약](ARCHITECTURE.md#작업-공간-복구와-실행-보관)을 참고하세요.

## 저장 범위와 보존 한도

| 데이터 | 저장·보존 |
|---|---|
| 인계 메모 | Orca 전용 plugin storage `neon.today.v1`, 새 기록을 추가하며 개수만으로 기존 기록을 삭제하지 않음 |
| 이어하기 시작 영수증 | 같은 저장 키, 중복 방지에 필요한 기존 영수증을 자동으로 잘라내지 않음 |
| 최신 인계 표시·현재 지문 검사 | 작업 공간별 최신 메모. UI는 6개씩, API는 요청한 페이지의 비교 가능한 메모만 검사 |
| 화면의 세션 조회 | 최대 80개 요청. 호스트가 생략을 알리면 `sessionsTruncated`와 경고 |
| 활성 Auto App 실행 | runtime storage, 최대 40개 |
| 보관한 Auto App 실행 | runtime storage의 `archivedRuns`, 최대 200개. 한도를 넘으면 보관 거부 |
| 배정 결과·검증 자료 | `~/.toris-neon/runs/`, 보관으로 자동 삭제하지 않음 |
| 기존 일지 | 사용자가 지정한 위치, 읽기 전용 |

페이지와 미리보기의 표시 한도는 저장 기록의 삭제 정책이 아닙니다. Orca 저장소 자체의 오류나 용량 제한으로 저장에 실패하면 성공으로 처리하지 않습니다. 실행 보관 상한도 기존 이력을 지우는 방식으로 우회하지 않습니다.

인계와 실행 데이터는 공개 GitHub 소스 저장소에 저장하지 않습니다. 한 호스트의 Orca 상태이며, 여러 컴퓨터 사이에서 메모·작업 공간·세션을 자동 동기화하지 않습니다. 다른 호스트에서 이어가려면 해당 프로젝트와 필요한 실행 도구·문맥을 사용자가 준비해야 합니다.

## 요청 예시

아래는 HTML 패널 내부의 RPC 예시입니다. 실제 `workspaceId`는 Orca에서 조회한 값을 사용합니다.

```js
await window.orca.plugin.request("today.save", {
  workspaceId,
  state: "로그인 UI 구현, 오류 상태 검토 대기",
  next: "실패 시나리오를 재현하고 오류 상태 테스트 추가",
  why: "테스트 계정 대기",
  hold: "이메일 인증 방식",
  verified: "실제 수행한 테스트 명령과 결과"
});

const snapshot = await window.orca.plugin.request("today.snapshot", {
  workspaceId,
  noteOffset: 0,
  noteLimit: 6
});

// snapshot.notesPage: {offset, limit, total, hasMore}
// 다음 페이지는 offset + 실제 반환된 notes.length부터 요청합니다.
if (snapshot.notesPage.hasMore) {
  const nextPage = await window.orca.plugin.request("today.snapshot", {
    workspaceId,
    noteOffset: snapshot.notesPage.offset + snapshot.notes.length,
    noteLimit: 6
  });
}

await window.orca.plugin.request("today.resume", {
  workspaceId,
  agent: "codex"
});

// 확인한 기존 세션을 재개할 때
await window.orca.plugin.request("today.resume", {
  workspaceId,
  sessionId
});
```

`noteOffset`은 0 이상의 정수, `noteLimit`은 지정 시 1–100입니다. 두 옵션을 생략하면 모든 작업 공간의 최신 인계를 반환합니다. `notesPage.total`은 최신 인계가 있는 작업 공간 수이며 전체 저장 메모 개수와 다릅니다. `workspaceId`는 이전 에이전트 세션 조회 범위를 지정하고, 인계 페이지와 실행 타임라인은 전체 작업 공간을 대상으로 합니다.

기본 화면은 새로고침 시 첫 6개 인계 페이지를 다시 읽고, 더 보기를 선택하면 이후 페이지를 이어 표시합니다. 오늘·어제 타임라인은 인계 카드의 페이지 크기로 잘라내지 않습니다.

Orca 호스트 API 계약은 설치된 버전의 `orca skills get orca-plugin-authoring` 안내를 따릅니다. 구현에 사용하는 주요 API는 `workspace.list`, `agent.listSessions`, `agent.launch`, `agent.resume`, `agents.list`, `terminal.list`입니다.
