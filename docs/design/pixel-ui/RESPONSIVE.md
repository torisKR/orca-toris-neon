## 패널 너비와 공통 규칙

| 모드 | `#app` 컨테이너 안쪽 너비 | 바깥 여백 · 열 간격 |
| --- | --- | --- |
| 좁음 | ≤ 560px | 현재 여백과 세로 순서 유지 |
| 중간 | 560px 초과, 900px 미만 | 양쪽 16–24px · 12px |
| 넓음 | ≥ 900px | 양쪽 20–32px · 16px |

- `#app { container: neon-panel / inline-size; }`를 선언한다. 중간은 `@container neon-panel (width > 560px)`, 넓음은 `@container neon-panel (width >= 900px)`로 적용한다. 561px, 900px은 정수 기준의 첫 너비다. 기존 팀 카드 480px, Play 행 420px 예외도 패널 컨테이너 기준으로 옮긴다. 작업실의 레인 수는 작업실 자체의 명명된 컨테이너에서 결정한다.
- 탭과 상태 헤더는 패널 너비를 쓴다. 각 열은 `minmax(0, …)`, 열 내부는 `min-inline-size: 0`을 쓴다. 문단, 도움말, 근거 설명은 `max-inline-size: min(100%, 72ic)`로 약 72칸을 상한으로 두고 `word-break: keep-all; overflow-wrap: anywhere`를 적용한다. 파일 경로와 패키지 문자열도 줄바꿈할 수 있게 둔다.
- 기존 좁은 탭의 표시값, 버튼, 상세 펼침, 현재 작업 공간과 빈 상태를 유지한다. 넓은 레이아웃은 같은 요소를 재배치한다. 패널 폭 변경만으로 선택한 실행·단계, 필터, 펼친 상세, 포커스를 재설정하지 않는다.
- 본문의 기본 읽기 순서와 키보드 순서를 맞춘다. 제목·선택·행동, 작업 내용, 상세와 기록 순서다. 작업실에서 단계를 열면 기존 상세 이동과 Escape 복귀를 유지한다. 포커스가 들어오는 위치는 상단 고정 내비게이션 높이만큼 `scroll-margin-block-start`를 둔다.

### Auto App

- 실행이 여러 개면 헤더의 짧은 선택 줄에 기존 `#run-select`, 선택 실행 제목, 선택 가능한 실행 수를 둔다. 실행 하나에서는 같은 자리에 제목만 표시해도 된다. 좁음에서는 기존 선택기와 옵션을 유지한다. 버튼과 진행 수는 말줄임보다 줄바꿈이 우선이다. 긴 실행 제목은 잘라 표시하고 기존 전체 제목 접근을 유지한다.
- 단계 상세는 넓음에서 `position: sticky; align-self: start`로 작업실과 시작 높이를 맞춘다. sticky의 상단 위치는 실제 스크롤 영역의 고정 내비 하단에서 12px이다. 상위 그리드에 `overflow: hidden`을 두지 않는다. 상세가 남은 스크롤 영역보다 길면 자연스럽게 페이지와 함께 스크롤해서 폼 끝까지 접근한다.
- 단계 위치는 `node.deps`의 위상 순위를 따른다. 같은 순위는 `run.nodes` 순서대로 같은 줄에 배치한다. 기존 조사→기획처럼 선행·후속 모두 하나인 시작 사슬은 한 줄에서 좌→우로 이을 수 있다. 그다음은 위→아래. 중간·넓음에서 한 레인 본체 최소 152px, 간격 12–16px를 예약한다. 작업실 안쪽 ≥560px이면 최대 3레인, 그 외엔 2레인이다. 같은 순위가 더 많으면 추가 줄에 배치하고 같은 분기임을 선으로 유지한다. 단독 단계는 유일한 선행 레인을 이어 쓰고, 여러 선행이 합류하면 가운데 레인을 쓴다.
- 분기·합류 간격은 36–48px, 방향을 바꿀 때는 90°로 꺾는다. 서로 다른 연결에는 카드 상·하단의 구분된 포트를 부여하고 최소 10px 간격을 둔다. 경로가 긴 경우 임시 공유선 대신 측면 배선 홈에서 실제 출발·도착 포트를 잇는다. 시각적으로 겹치면 한 선에 6px 단절을 넣어 교차를 표현한다. 그래프 자체는 카드 너비만큼 줄바꿈하고 패널 전체 가로 스크롤을 만들지 않는다.
- 기본 그래프의 `test → policy`와 `test → listing`은 출시 준비를 접었을 때 해당 펼침 헤더의 명시된 포트에서 끝난다. 펼치면 원래 단계를 잇는다. 실제 상태를 가진 출시 단계의 기존 자동 펼침 동작을 유지한다. 선택한 단계가 접힘 안에 있다면 상세를 열 때 함께 펼친다. 수정 요청의 역방향 표시는 별도 정적 표식으로 유지하고 공급선 데이터에 합치지 않는다.
- 시작점에 선행 단계가 없으면 카드 바로 앞에 16–24px짜리 입력 포트를 그린다. 접근성 설명에 `시작 포트`를 사용한다. 추가 단계와 이전 템플릿은 동일한 순위화 규칙으로 배치한다. 빠진 의존 ID의 선은 생략하고 유효한 선행을 꾸며 내지 않는다.

### 오늘 이어하기 · 에이전트 · Play Store

- 실행 경로는 위상 순위대로 이어진 단계 버튼을 각 실행 행 안에 표시한다. 병렬 그룹 양옆에 분기/합류 괄호를 두고 그 안에 단계 버튼을 모은다. 폭이 모자라면 그룹 경계에서 다음 줄로 이어진다. 그룹 자체가 폭보다 넓으면 괄호 안에서 개행한다. 출시 준비처럼 이어지는 묶음도 같은 행에서 연속 경로로 읽히게 한다. 작은 경로는 공급 중 화살표, 대기 점, 멈춤 소포, 통과 체크를 정지로 그린다. 클릭하면 기존 단계 상세를 연다. 건너뜀도 경로에 남기고 통과 수에는 넣지 않는다.
- Orca 스트립은 `ui.state.agents`와 기존 `workspaceRoom()`의 작업 상태, 세션 열기, 직접 실행/Neon 배정에 대한 표기를 쓴다. Neon 한도는 `ui.state.limits`의 `active/activeJobs`와 `heavy/heavyJobs`를 그대로 사용한다. 빌드·테스트는 전체의 부분집합이며 직접 실행 세션은 Orca 스트립에만 표시한다. 팀당 현재 우선순위로 고른 대표 단계와 기존 배정 편집을 유지한다.
- Play Store는 헤더와 모든 `summary`에 공통 `grid-template-columns: minmax(115px,1.1fr) minmax(150px,1.5fr) minmax(145px,1fr) minmax(80px,.65fr) minmax(105px,.75fr)`를 적용한다. 행 전체를 기존 `details/summary`로 유지하고 셀에도 읽을 수 있는 텍스트 접두어를 둔다. 스탬프가 여러 개면 셀 안에서 줄바꿈한다. 앱 이름/패키지는 `item.name/packageName`, 상태는 기존 `statuses/check`, 트랙 수는 `item.tracks.length`를 쓴다. 마지막 확인은 해당 앱 트랙의 유효한 `observedAt` 중 최신 시각이다. 실패 및 이전 성공 기록은 기존 오류/재확인 도장과 상세로 표시한다. 관측값이 없으면 `미확인`으로 표시한다. 계정 전체의 `checkedAt`은 상단 계정 정보에 별도로 유지한다.

## 공급선 상태

연결 ID는 `(run.id, source.id, target.id)`다. 단계의 최신 `stagePixelOf()` 결과(`pose/motion/phase/until`)를 그대로 사용한다. 실제 연결은 `target.deps`에서만 만들고, 소포 이동은 출발에서 도착 방향이다. 시작 포트만 출발 단계 없는 예외다. 한 연결을 따라 출발 카드의 폼 내용이나 보고서 자체가 이동한다는 뜻은 없다.

아래는 우선순위 순서다. 두 작업이 같은 선행 단계에서 갈라지면 각각 `live`로 판정한다. 다른 가지에서 막혀도 도착 단계의 작업 증거가 살아 있는 가지는 계속 흐른다.

| 상태 | 선과 포트 | 모션과 타이밍 | 접근성 문구 | 최신 데이터 |
| --- | --- | --- | --- | --- |
| 실행 완료 또는 지나간 연결 `complete` | 단색 민트 실선과 작은 체크. | 정지. 완료와 같은 push에서 모든 레일을 정리한다. | `완료` | 먼저 `run.status === 'completed'`. 실행 중에는 이미 처리된 도착 `pose === 'passed'`로 들어오는 실제 연결에 적용한다. |
| 멈춤 `stopped` | 회청색 레일 끝에 고정 소포(분홍). 조용함·시작 신호 지연·승인 등 경고는 호박색. 조용함은 정지의 두 막대 마크. 카드에는 기존 단계 아이콘과 이유. | 진입 즉시 움직이는 소포를 내리고 도착 포트에 고정 소포 한 개를 둔다. | `멈춤`과 기존 이유. 조용함은 마지막 작업 신호 기준임을 알린다. | `blocked / failed / quiet / start-slow / retry / unknown / approval / report / paused / cancelled`. `ui.cancelling` 또는 `run.status === 'cancelled'`는 미완료 연결의 모션을 즉시 끈다. 작업 중인 배정이 있는 `run.status === 'paused'`는 `stagePixelOf()` 결과를 따른다. |
| 작업 확인 `live` | 회청색 파이프 안에 민트 소포(작업) 또는 라일락 소포(검토). 정지 모드에서는 진행 방향 화살표. | 6×6px 소포, 40px 간격, 1.2초마다 40px 이동. `steps(10, end)`으로 4px씩 전진한다. | `공급 중` (검토일 때 `검토 · 공급 중`). | 도착 `pose === 'work' || pose === 'review'` 및 `motion === 'loop'`, 출발은 `passed` 또는 실제 건너뜀을 잇는 전달 포트. 선행이 없는 경우 시작 포트. 현재 nonce의 `jobs/operations`, `promptSeen/sessionId/lastAgentEventAt`, 자체 전송 결과와 `workingCheckedAt` 모두 기존 상태 판정에서 읽는다. |
| 방금 통과한 인계 `handoff` | 회청색 파이프를 소포 한 개가 끝까지 이동. 멈춤 모드에서는 접수 포트 바로 앞의 방향 마크만 보인다. | 720ms, `steps(18, end)`, 1회. 완료 후 곧바로 현재 선 상태로 돌아간다. | `인계` | 출발 단계의 이전 관측 상태가 통과 전이고 이번 최신 상태의 `node.status === 'passed'`, `node.completedAt`은 유효한 새 값. 도착 후보가 이미 일하고 있으면 계속 흐르는 `live`에 맡긴다. |
| 슬롯·선행 대기 `queue` | 실선 레일, 도착 쪽 작은 호박색 점 세 개. 여러 선이 하나의 단계로 합쳐지면 대기 점은 포트별로 겹치지 않게 놓는다. | 정지. | `대기` 및 `슬롯 대기`, `선행 대기` 등 현재 이유. | 도착 `pose === 'queue' || pose === 'dependency'`, `waiting[node.id]`, `node.deps`, `limits`. |
| 미배정, 시작 준비, 건너뜀 `idle` | 옅은 분절선. 건너뜀은 단계 카드의 우회 표식으로 표시한다. | 정지. | `대기` 또는 `건너뜀` | 도착 `pose === 'idle' || pose === 'start' || pose === 'skipped'`와 초기 실행의 `run.started`. |

- `work/review`의 유효기간은 기존 `until`을 따른다. 처음에는 작업 이벤트 시각에서 180초, Orca가 여전히 작업 중임을 확인했다면 `workingCheckedAt + 150초`까지만 같은 증거를 쓴다. `updatedAt`, 시작 시각, 검토 시작 안내, 슬롯 점유, 푸시만으로 공급을 시작하거나 연장하지 않는다. 증거가 빠졌거나 이전 배정의 증거면 해당 연결은 정지다.
- 인계는 매번 새 통과를 관측한 시점에 한 번 계산한다. 처음 읽은 스냅샷은 기준값으로만 저장한다. 도착 후보는 실제 후속 단계 중 현재 `idle/start`이고 모든 선행이 `passed/skipped`인 첫 단계(`run.nodes` 순서)다. 슬롯/선행 대기, 정지, 이미 통과한 도착 단계와 새 배정 중지에서는 인계만 생략한다. 따라서 대기·정지 표식이 있는 선 위에는 이동이 생기지 않는다. 리셋 뒤 새 시각으로 다시 통과하면 새 전환으로 취급한다.
- 단발 키는 `(run.id, node.id, completedAt)`다. 수신 시 고른 도착을 이 키에 묶고, 숨겨진/다른 탭에서는 애니메이션을 열지 않는다. CSS 지연에 `-(now - observedAt)`을 넣어 중간 재렌더가 남은 구간만 보여 주게 한다. 720ms를 지나거나 중간에 대기/멈춤·취소·완료/그래프 변경이 도착하면 창을 닫는다. 숨김 뒤 복귀, 실행 선택, 펼침, 화면 리사이즈, 상세 GET, 중복 summary에서 재생하지 않는다. 캐시에 이미 있는 `task.passed` 이벤트는 검증 보조값이다.
- 안정된 DOM 키로 출발·도착에 연결된 레일과 도착 표식을 함께 갱신한다. push와 기존 시각 경계 갱신 양쪽에서 새 포즈를 적용한다. 경계에 도달한 작업의 공급이 틱 대기 동안 남지 않도록 마크·포즈 공통의 가장 빠른 `until`에 단일 가시 타이머를 예약한다. 시간 문구는 기존 5초 틱을 계속 쓴다. 편집 중 전체 재렌더를 미룰 때도 배선·작업 포즈만 최신 값으로 대조한다. 이전 배선을 검증할 수 없으면 공급을 정지시킨다. 창이 숨겨지면 모션을 끄고, 보이면 최신 요약과 현재 시각으로 재판정한다.

## 픽셀 에셋과 접근성

- `flow-marks.png`는 48×8 투명 RGBA 마스크다. 왼쪽부터 8×8 셀에 소포, 우향 화살표, 세 점, 정지 소포, 완료 체크, 두 막대를 담는다. 1×는 요약 행, 2×(16×16)는 작업실 포트와 범례다. `image-rendering: pixelated`, 정수 좌표·배율을 쓴다. 기존 `marks.png`와 팀 아틀라스는 그대로 사용한다.
- 파이프는 `flow.css`의 6px 외곽과 4px 어두운 홈을 쓴다. 작업 파형은 6px 길이의 대시를 `stroke-dashoffset`으로 이동한다. 단발 경로는 `pathLength="100"`인 같은 SVG 경로에 대시 하나를 그린다. 꺾임을 포함해 레일에 맞춘다. SVG 좌표는 DOM 레이아웃이 변할 때만 읽고 SVG 단위를 실제 CSS 픽셀에 맞춘다. 경로 마크는 CSS 레이아웃으로 포트에 고정한다. 움직임은 CSS와 브라우저가 처리한다. 캔버스, 프레임마다 실행되는 JS, 네트워크 에셋은 사용하지 않는다.
- `prefers-reduced-motion: reduce` 또는 작업실의 `공급 모션 끄기`(`aria-pressed`)가 활성화되면 소포 이동을 끄고 활성 선과 인계 선에 정지 화살표를 남긴다. 켜기/끄기는 공급 표시만 바꾸고 실행 상태와 포즈 판정에 영향을 주지 않는다. 두 정지 조건 가운데 하나라도 활성화돼 있으면 재생하지 않는다. 오늘 탭의 작은 경로는 기본부터 정지다.
- 공급선 SVG와 픽셀 마크는 `aria-hidden`. 도착 단계의 툴팁/accessible name에 연결 상태를 넣는다. 여러 입력은 `제품 기획에서 공급 중 · 화면 설계에서 대기`처럼 넣을 수 있다. 실시간 알림은 포즈나 연결 상태가 실제로 바뀔 때 기존 polite 채널을 사용한다. CSS 루프의 각 소포와 시간 문구를 다시 알리지 않는다. 고대비 모드에서도 모양·방향·문구로 구분한다.
- 런타임 에셋은 `panel/` 안에서 상대 URL로 불러온다. `flow.css + flow-marks.png`는 150KB 예산보다 작다. 시안 파일은 개발 참고 자료이고 런타임에서 로드하지 않는다.

기존 프리뷰는 네 탭을 340·520·760·1000·1280px에서 비교했다. 기존 레이아웃은 모든 너비에서 주요 섹션을 세로로 쌓고, 760px 이상에서도 작업실·앱 목록의 행이 탭 전체 너비로 길어졌다. 새 배치는 아래의 수락 기준으로 확인한다.

1. 560/561px, 899/900px에서 브라우저 폭을 고정한 채 패널만 바꿨을 때 레이아웃이 바뀌고 상세 폼 상태가 유지된다. 340·520px에서 기존 액션과 정보를 찾을 수 있다.
2. 동일 실행에서 두 활성 가지는 각각 흐르고, 멈춘 가지는 정지한다. 상태 push, 신호 시각 만료, 취소, 완료, 가시성 복귀가 각각 카드와 선에 반영된다. 슬롯 대기, 시작 안내, 선택 변경만으로 공급이 생기지 않는다.
3. 통과 전후 push 사이에서만 인계가 한 번 보인다. 중복 push, 탭 재진입, 펼침, 끝난 실행은 인계를 재생하지 않는다. 멈춤 모드에서 상태와 방향을 읽을 수 있다.
4. 좁은 패널과 넓은 패널에서 키보드로 모든 단계·앱 상세를 열 수 있다. 실제 Orca 패널에서 스크롤 컨테이너·고정 상세, 상대 에셋 로딩, 실시간 신호와 오래 열린 편집 폼의 갱신을 확인한다.
